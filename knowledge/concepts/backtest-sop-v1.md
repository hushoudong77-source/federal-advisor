## 一、回测框架总览

```
┌─────────────────────────────────────────────────────┐
│              定期回测四层架构                          │
├─────────────┬─────────────┬─────────────────────────┤
│ L1 周度     │ 每周六      │ 全池买入区间命中率回测     │
│ L2 月度     │ 每月1日     │ 逐标最优参数重标定（24月滚动窗口 + 全量窗口对比） │
│ L3 季度     │ 1/4/7/10月1日 │ 系统整体绩效审计 + 结构优化 │
│ L4 校验     │ 参数提案时   │ 样本外校验（70/30时间序列分割）│
├─────────────┴─────────────┴─────────────────────────┤
│ 触发式（不限时）：事故驱动 → 即时回测 → 即时修正       │
└─────────────────────────────────────────────────────┘
```

**核心原则**：
- 回测窗口统一为 **滚动 250 个交易日**（约 1 自然年），保证统计显著性
- 回测基准：**买入后持有 60 个交易日**，评估区间收益
- 所有回测输出必须包含：胜率、平均收益、最大回撤、夏普比率（若数据允许）
- 回测结果若触发参数修正，必须走完整的「提案 → 黑帽审计 → CEO 裁决 → 法典修正」流程，严禁直接修改

## 二、L1 周度回测：买入区间命中率（每周六）

### 2.1 回测内容

| 维度 | 说明 |
|:---|:---|
| **触发时间** | 每周六（A股+美股均休市） |
| **数据窗口** | 滚动 250 个交易日 |
| **覆盖标的** | 全池 21 只（含 SMIN 禁购观察/VTI/VEA空仓临时路由） |
| **核心指标** | 买入区间命中率 = 区间内天数 / 总交易日数 |

### 2.2 执行步骤

```
Step 1: 逐标计算 MA20（或 MA120/MA60）× ATR 乘数 → 买入区间上下沿
Step 2: 回测窗口内每日收盘价 vs 买入区间，统计命中天数
Step 3: 分市场（A股/美股/其他）汇总命中率
Step 4: 对比上周命中率，识别异常变化（±10%以上标注）
```

### 2.3 输出格式

| 标的 | 买入区间 | 命中天数 | 命中率 | 较上周 | 信号 |
|:---|:---|:---:|:---:|:---:|:---:|
| 510300 | ¥4.59~4.71 | 32/250 | 12.8% | +2.1% | 🟢 |
| QQQ | $608~647 | 15/250 | 6.0% | -3.2% | 🔴 |

### 2.4 熔断触发

| 条件 | 动作 |
|:---|:---|
| 全池命中率 < 10% 连续 4 周 | 触发 L2 提前审计，排查 MA20 锚线是否结构性失效 |
| 单只标的命中率 < 3% 连续 4 周 | 该标的降级审查：是否需调整 ATR 乘数或切换锚线 |
| 单只标的命中率 > 40% | 区间过宽警告，核查 ATR 乘数是否偏大 |

## 三、L2 月度回测：逐标最优参数重标定（每月1日）

### 3.1 回测内容

这是整个回测体系的核心——**每月重新标定每只标的的最优 ATR 乘数**。

**回测窗口**：滚动最近 24 个月（约 500 个交易日），捕捉近期市场结构变化。

**首次执行特殊条款（2026-06-01）**：
- 同时跑 **全量窗口**（2020至今所有可用数据）和 **24月滚动窗口**
- 对比两组最优参数差异
- 若 CAGR 差异 < 1pp（绝对值）→ 月度重标定降级为季度重标定（节省算力）
- 若 CAGR 差异 ≥ 1pp → 月度重标定确权为必要，此后每月执行

### 3.2 回测矩阵

对每只标的，遍历以下参数组合：

```
ATR 乘数范围：1.0 ~ 5.0（步长 0.5，共 9 档）
锚线类型：MA20 / MA60 / MA120（仅 518880/159302 保留多锚线测试）
买入区间 = [MA_anchor − m×ATR, MA_anchor]
```

对每组参数，计算：
- **命中率**（区间内天数 / 500）
- **命中后 60 日平均收益**
- **命中后 60 日胜率**（正收益天数占比）
- **命中后 60 日最大回撤**
- **综合得分 = 胜率 × 平均收益 − 最大回撤 × 0.5**

### 3.3 最优判定逻辑

```
if 当前参数综合得分 < 最优参数得分 × 0.85:
    → 触发参数修正提案
elif 当前参数综合得分 < 最优参数得分 × 0.95:
    → 标记观察，下月再议
else:
    → 维持当前参数
```

**0.85 阈值的设计逻辑**：防止过度拟合。只有最优参数显著优于当前参数（>15% 得分差距）才触发修正，避免因短期噪音频繁调整参数。

### 3.4 历史最优参数档案

| 标的 | 当前乘数 | 当前得分 | 历史最优乘数 | 最优得分 | 差距 | 状态 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| QQQ | 4.0x | — | — | — | — | 待标定 |
| 510300 | 2.0x | — | — | — | — | 待标定 |
| ... | ... | ... | ... | ... | ... | ... |

### 3.5 修正提案流程

```
Step 1: 输出参数对比表
Step 2: 黑帽审计：攻击新参数（过拟合风险？窗口特殊性？）
Step 3: CEO 裁决：通过 → 修正法典对应参数
Step 4: 记录修正日志到 knowledge/analysis/
```

### 4.1 回测内容

|:---|:---|
| **触发时间** | 1月/4月/7月/10月 1日 |
| **数据窗口** | 滚动 500 个交易日（约 2 年） |

### 4.2 审计项目

#### 4.2.1 规则引擎有效性审计

| 审计项 | 方法 | 判定标准 |
|:---|:---|:---|
| 买入区间有效性 | 命中后 60 日胜率 | < 55% → 规则失效警告 |
| 止损有效性 | 止损触发后 20 日平均继续跌幅 | 继续跌幅 > 5% → 止损有效 |
| 动态止盈有效性 | 止盈触发后 20 日平均继续涨幅 | 继续涨幅 > 3% → 止盈过早警告 |
| US10Y 熔断有效性 | 熔断期间 vs 非熔断期间 60 日收益差 | 收益差 < 0 → 熔断无效警告 |

#### 4.2.2 组合层面审计

| 审计项 | 方法 |
|:---|:---|
| 年化收益率 | 模拟组合净值 CAGR |
| 最大回撤 | 模拟组合净值峰值到谷底 |
| 夏普比率 | （CAGR − 无风险利率）/ 年化波动率 |
| 胜率 | 盈利交易 / 总交易 |
| 盈亏比 | 平均盈利 / 平均亏损 |
| 现金占用率 | 平均持仓仓位 / 总资产 |

#### 4.2.3 结构优化审计

| 审计项 | 说明 |
|:---|:---|
| 标的池有效性 | 各标的独立贡献归因，负贡献连续 3 季度 → 降级审查 |
| 仓位规则有效性 | 三档仓位（低/中/高）实际表现对比 |
| 锚点体系有效性 | 宏观熔断触发次数 vs 实际市场转折匹配度 |

## 六、L4 样本外校验（参数修正提案强制前置 — 2026-07-08 焊入 | V1.4 数据最大化+三段回测标准化 — 2026-07-30）

### 6.1 为什么需要 L4

**根因**：L1-L3 回测 + 触发式回测全部使用全量历史数据选择最优参数。这等价于「事后诸葛亮」——你在 2020 年不可能知道 2026 年的走势，但参数选择时已经偷看了 2026 年的数据。这就是**前视偏差（Look-ahead Bias）**。

**血证**：513770 在 V27 全量回测中表现不错，被选入核心池。但近 250 日实战窗口 19 连败——全量回测选出的参数在样本外彻底失效。

**L4 的职责**：在任何参数修正提案进入黑帽审计之前，用样本外数据验证——新参数在「没见过」的数据上是否仍然有效。不是替代 L1-L3，而是在它们产出提案后加一道样本外闸门。

### 6.2 触发条件

| 触发源 | 场景 |
|:---|:---|
| L2 月度回测 | L2 输出参数修正提案（得分比 < 85%）→ 自动触发 L4 |
| 触发式回测 | 任何参数修正提案 → 自动触发 L4 |
| 手动 | `/回测 L4 <标的> <参数>` |

**L4 不独立运行**——它是参数修正提案的验证步骤，不产出独立提案。

### 6.3 数据取数强制规则（V1.4 焊入 — 2026-07-30）

**这是 L4 校验最关键的步骤——数据窗口必须最大化，否则样本外数据量不足导致统计结论不可靠。**

#### 6.3.1 取数原则（不可违反）

```
🔴 数据窗口最大化铁律：
  ├── 每个标的必须追溯到 Tushare 能返回的最早日线
  ├── start_date = 标的上市日期（或 Tushare 最早可用日期）
  ├── end_date = 最近一个交易日
  ├── ⛔ 禁止写死 start_date（如 '2024-01-01'）
  ├── ⛔ 禁止假设「这个标的只有 X 年数据」而不实际尝试更早日期
  └── ⛔ 禁止使用记忆/缓存中的行数来判断数据是否完整
```

#### 6.3.2 取数执行步骤

```
Step 0: 确定标的上市日期
  ├── A股ETF → 查询基金成立日期（如 510880 成立于 2006-11-17，上市 2007-01-18）
  ├── 美股ETF → 查询 ETF 成立日期（如 VNM 成立于 2009-08-11）
  └── 不确定时 → start_date = '2000-01-01'（Tushare 会自动返回最早可用数据）

Step 0.5: 调用 Tushare 拉取全量日线
  ├── 美股: pro.us_daily(ts_code='XXX', start_date='上市日', end_date='今天')
  ├── A股: pro.fund_daily(ts_code='XXX.SH/.SZ', start_date='上市日', end_date='今天')
  └── 验证: 打印 len(data) 和 data['trade_date'].min() / max()

Step 0.6: 数据量校验
  ├── 行数 ≥ 500 → ✅ 足够做三段分割
  ├── 行数 200-500 → ⚠️ 可做三段分割但样本外窗口短，标注「低置信」
  ├── 行数 < 200 → 🔴 数据不足，跳过该标的 L4，标注「数据窗口过短」
  └── ⛔ 禁止行数不足时强行三段分割
```

#### 6.3.3 常见错误与纠正

| 错误 | 纠正 |
|:---|:---|
| 凭记忆写 start_date='2024-03-01'（513910 上市日） | 实际调用 Tushare，让它返回从上市日至今的全量数据 |
| 上次回测用了 2024-2026，这次直接用同样窗口 | 每次回测独立拉取，不依赖上次的窗口参数 |
| 认为「A股 ETF 数据只到 2020 年」而不尝试更早 | 510880 可追溯到 2007 年，510500 可到 2013 年 |
| 拉取后不检查 len() 就直接用 | 必须打印行数 + 日期范围确认数据完整 |

### 6.4 三段分割法

```
全量历史数据（从上市日 ~ 今天）
    │
    ├── 前 70%（按时间）→ 样本内（训练集）
    │   └── 用途：遍历参数组合，选出最优参数
    │
    ├── 后 30%（按时间）→ 样本外（验证集）
    │   └── 用途：用样本内选出的参数，在未见过的数据上验证
    │
    └── 全量（100%）→ 对照基准
        └── 用途：最终报告全量表现作为参考
```

**关键约束**：
- 分割是**时间序列**分割，不是随机分割。金融数据有时间依赖性，随机分割会引入前视偏差
- 分割点 = 全量数据总交易日 × 0.7，取整到最近交易日
- 样本内和样本外的回测方法完全相同（同一套买入/卖出规则），仅数据窗口不同

### 6.5 执行步骤

```
Step 1: 确定全量数据窗口
  → start_date = 标的上市日期（或最早可用数据）—— 遵循 §6.3 取数强制规则
  → end_date = 最近交易日
  → ⛔ 禁止写死 start_date，必须追溯到 Tushare 最早可用日

Step 2: 计算分割点
  → 总交易日 N = len(全量日线)
  → 分割点 = N × 0.7（取整）
  → 样本内: [0, 分割点]
  → 样本外: [分割点+1, N-1]

Step 3: 样本内训练（前 70%）
  → 在样本内数据上遍历参数组合
  → 计算每组参数的综合得分
  → 选出得分最高的参数组合 = 候选参数

Step 4: 样本外验证（后 30%）
  → 用候选参数在样本外数据上回测
  → 计算样本外的综合得分
  → 对比全量得分 vs 样本外得分

Step 5: 输出 L4 校验报告
```

### 6.6 通过标准

| 样本外表现 | 判定 | 动作 |
|:---|:---|:---|
| 样本外胜率 ≥ 样本内胜率 × 0.70 | ✅ 通过 | 参数提案进入黑帽审计 |
| 样本外胜率 ∈ [样本内×0.50, 样本内×0.70) | 🟡 警告 | 提案降级，标注「样本外衰减风险」 |
| 样本外胜率 < 样本内胜率 × 0.50 | 🔴 否决 | 提案驳回，候选参数疑似过拟合 |
| 样本外交易笔数 < 5 | 🔴 否决 | 样本量不足，无法得出统计结论 |

**核心逻辑**：样本外表现不需要优于样本内——那几乎不可能。但样本外不能崩盘（胜率砍半以下）。胜率衰减 30% 以内是可接受的泛化误差，衰减超过 50% = 参数过拟合了样本内。

### 6.8 与 L2 的整合

L2 月度回测输出参数修正提案后，**自动追加 L4 校验段落**（不单独触发指令）：

```
# 📐 /回测 L2 — [月度参数重标定输出]
    │
    ├── 逐标优化结果表
    ├── 分类裁决（建议修正/观察/维持）
    │
    └── 🔴 对每个「建议修正」标的，自动跑 L4 样本外校验
        ├── 通过 → 修正提案附带「L4 ✅」标记
        ├── 警告 → 修正提案降级为「观察」
        └── 否决 → 修正提案撤回，记录否决理由
```

### 6.9 自检熔断

- 触发：任何参数修正提案进入黑帽审计前未经过 L4 校验 → **L4 跳过违规，提案无效**
- 触发：L4 分割使用了随机分割而非时间序列分割 → **前视偏差违规**
- 触发：样本外交易笔数 < 5 但判定为通过 → **样本量不足违规**
- 触发：L4 否决的提案被提交到黑帽审计 → **严重违规，提案立即撤回**
- 🔴 触发：start_date 写死而非追溯到 Tushare 最早可用日 → **取数窗口违规（§6.3）**
- 🔴 触发：拉取后未打印 len(data) + 日期范围确认 → **数据完整性校验跳过违规**
- 🔴 触发：行数 < 200 仍强行三段分割 → **数据不足强行回测违规**

## 十、定时提醒与自动执行机制

### 9.1 设计原则

联邦投顾在每次对话启动时自动检查当前日期，命中回测日则自动触发执行。回测执行由联邦投顾自动跑数据，结果提交统帅裁决——**统帅只管「批不批」，不负责「跑不跑」。**

**实现方式**：依赖 AGENT.md 模块零的「对话启动日期检查」机制（非 scheduler 定时推送）。每次联邦投顾与统帅对话启动时，自动读取当前日期并与回测日历比对。命中则立即执行。此机制不依赖外部定时推送，由对话驱动。

### 9.2 提醒触发表

| 触发日 | 回测层级 | 触发条件 | 动作 |
|:---|:---|:---|:---|
| **每周六** | L1 周度 | 当前日期为周六 | 自动执行全池买入区间命中率回测，输出结果表 |
| **每月1日** | L2 月度 | 当前日期为每月1日 | 自动执行逐标最优参数重标定（24月滚动窗口），输出参数对比→对建议修正标的自动跑L4→黑帽审计→提交CEO裁决 |
| **1/4/7/10月1日** | L3 季度 | 当前日期为1/4/7/10月1日 | 自动执行系统整体绩效审计，输出完整季度报告 |
| **参数提案触发** | L4 校验 | L2/触发式回测输出参数修正提案 | 自动执行70/30样本外校验，通过→提案进入黑帽审计，未通过→提案驳回 |
| **即时** | 触发式 | 事故/连续3次止损/宏观熔断 | 即时执行，不受日历约束 |

### 9.3 执行协议（V1.2更新 — 2026-06-27 数据依赖迁移至Tushare）

```
每次对话启动 → 检查日期 → 命中回测日？
├── 是 → 自动拉取Tushare全量日线 → 自算全部指标 → 执行回测 → 输出结果 → 提交统帅裁决
│        └── 若数据不足（Tushare不可用/返回空）→ 输出「数据真空提醒」，推迟至下次对话
└── 否 → 正常对话流程
```

**数据依赖更新**：V1.0依赖"统帅供弹截图"，V1.2起改为Tushare全量日线自算（pro.us_daily + pro.fund_daily），无需守东截图投喂。
