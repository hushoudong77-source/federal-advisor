## 一、回测框架总览

```
┌─────────────────────────────────────────────────────┐
│              定期回测三层架构                          │
├─────────────┬─────────────┬─────────────────────────┤
│ L1 周度     │ 每周六      │ 全池买入区间命中率回测     │
│ L2 月度     │ 每月1日     │ 逐标最优参数重标定（24月滚动窗口 + 全量窗口对比） │
│ L3 季度     │ 1/4/7/10月1日 │ 系统整体绩效审计 + 结构优化 │
├─────────────┴─────────────┴─────────────────────────┤
│ 触发式（不限时）：事故驱动 → 即时回测 → 即时修正       │
└─────────────────────────────────────────────────────┘
```

**核心原则**：
- 回测窗口统一为 **滚动 250 个交易日**（约 1 自然年），保证统计显著性
- 回测基准：**买入后持有 60 个交易日**，评估区间收益
- 所有回测输出必须包含：胜率、平均收益、最大回撤、夏普比率（若数据允许）
- 回测结果若触发参数修正，必须走完整的「提案 → 黑帽审计 → CEO 裁决 → 法典修正」流程，严禁直接修改

## 二、L1 周度回测：买入区间命中率（每周六）

### 2.1 回测内容

| 维度 | 说明 |
|:---|:---|
| **触发时间** | 每周六（A股+美股均休市） |
| **数据窗口** | 滚动 250 个交易日 |
| **覆盖标的** | 全池 21 只（含 SMIN 禁购观察/VTI/VEA空仓临时路由） |
| **核心指标** | 买入区间命中率 = 区间内天数 / 总交易日数 |

### 2.2 执行步骤

```
Step 1: 逐标计算 MA20（或 MA120/MA60）× ATR 乘数 → 买入区间上下沿
Step 2: 回测窗口内每日收盘价 vs 买入区间，统计命中天数
Step 3: 分市场（A股/美股/其他）汇总命中率
Step 4: 对比上周命中率，识别异常变化（±10%以上标注）
```

### 2.3 输出格式

| 标的 | 买入区间 | 命中天数 | 命中率 | 较上周 | 信号 |
|:---|:---|:---:|:---:|:---:|:---:|
| 510300 | ¥4.59~4.71 | 32/250 | 12.8% | +2.1% | 🟢 |
| QQQ | $608~647 | 15/250 | 6.0% | -3.2% | 🔴 |

### 2.4 熔断触发

| 条件 | 动作 |
|:---|:---|
| 全池命中率 < 10% 连续 4 周 | 触发 L2 提前审计，排查 MA20 锚线是否结构性失效 |
| 单只标的命中率 < 3% 连续 4 周 | 该标的降级审查：是否需调整 ATR 乘数或切换锚线 |
| 单只标的命中率 > 40% | 区间过宽警告，核查 ATR 乘数是否偏大 |

## 三、L2 月度回测：逐标最优参数重标定（每月1日）

### 3.1 回测内容

这是整个回测体系的核心——**每月重新标定每只标的的最优 ATR 乘数**。

**回测窗口**：滚动最近 24 个月（约 500 个交易日），捕捉近期市场结构变化。

**首次执行特殊条款（2026-06-01）**：
- 同时跑 **全量窗口**（2020至今所有可用数据）和 **24月滚动窗口**
- 对比两组最优参数差异
- 若 CAGR 差异 < 1pp（绝对值）→ 月度重标定降级为季度重标定（节省算力）
- 若 CAGR 差异 ≥ 1pp → 月度重标定确权为必要，此后每月执行

### 3.2 回测矩阵

对每只标的，遍历以下参数组合：

```
ATR 乘数范围：1.0 ~ 5.0（步长 0.5，共 9 档）
锚线类型：MA20 / MA60 / MA120（仅 518880/159302 保留多锚线测试）
买入区间 = [MA_anchor − m×ATR, MA_anchor]
```

对每组参数，计算：
- **命中率**（区间内天数 / 500）
- **命中后 60 日平均收益**
- **命中后 60 日胜率**（正收益天数占比）
- **命中后 60 日最大回撤**
- **综合得分 = 胜率 × 平均收益 − 最大回撤 × 0.5**

### 3.3 最优判定逻辑

```
if 当前参数综合得分 < 最优参数得分 × 0.85:
    → 触发参数修正提案
elif 当前参数综合得分 < 最优参数得分 × 0.95:
    → 标记观察，下月再议
else:
    → 维持当前参数
```

**0.85 阈值的设计逻辑**：防止过度拟合。只有最优参数显著优于当前参数（>15% 得分差距）才触发修正，避免因短期噪音频繁调整参数。

### 3.4 历史最优参数档案

| 标的 | 当前乘数 | 当前得分 | 历史最优乘数 | 最优得分 | 差距 | 状态 |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|
| QQQ | 4.0x | — | — | — | — | 待标定 |
| 510300 | 2.0x | — | — | — | — | 待标定 |
| ... | ... | ... | ... | ... | ... | ... |

### 3.5 修正提案流程

```
Step 1: 输出参数对比表
Step 2: 黑帽审计：攻击新参数（过拟合风险？窗口特殊性？）
Step 3: CEO 裁决：通过 → 修正法典对应参数
Step 4: 记录修正日志到 knowledge/analysis/
```

## 四、L3 季度回测：系统整体绩效审计（1/4/7/10月1日）

### 4.1 回测内容

| 维度 | 说明 |
|:---|:---|
| **触发时间** | 1月/4月/7月/10月 1日 |
| **数据窗口** | 滚动 500 个交易日（约 2 年） |
| **模拟方式** | 假设严格按法典规则执行买入/卖出，模拟组合净值曲线 |

### 4.2 审计项目

#### 4.2.1 规则引擎有效性审计

| 审计项 | 方法 | 判定标准 |
|:---|:---|:---|
| 买入区间有效性 | 命中后 60 日胜率 | < 55% → 规则失效警告 |
| 止损有效性 | 止损触发后 20 日平均继续跌幅 | 继续跌幅 > 5% → 止损有效 |
| 动态止盈有效性 | 止盈触发后 20 日平均继续涨幅 | 继续涨幅 > 3% → 止盈过早警告 |
| US10Y 熔断有效性 | 熔断期间 vs 非熔断期间 60 日收益差 | 收益差 < 0 → 熔断无效警告 |

#### 4.2.2 组合层面审计

| 审计项 | 方法 |
|:---|:---|
| 年化收益率 | 模拟组合净值 CAGR |
| 最大回撤 | 模拟组合净值峰值到谷底 |
| 夏普比率 | （CAGR − 无风险利率）/ 年化波动率 |
| 胜率 | 盈利交易 / 总交易 |
| 盈亏比 | 平均盈利 / 平均亏损 |
| 现金占用率 | 平均持仓仓位 / 总资产 |

#### 4.2.3 结构优化审计

| 审计项 | 说明 |
|:---|:---|
| 标的池有效性 | 各标的独立贡献归因，负贡献连续 3 季度 → 降级审查 |
| 仓位规则有效性 | 三档仓位（低/中/高）实际表现对比 |
| 锚点体系有效性 | 宏观熔断触发次数 vs 实际市场转折匹配度 |

### 4.3 输出格式

```
═══════════════════════════════════════
  2026 Q2 系统整体绩效审计报告
═══════════════════════════════════════

一、模拟组合绩效
  年化收益：XX% | 最大回撤：XX% | 夏普：X.XX
  胜率：XX% | 盈亏比：X.X | 现金占用率：XX%

二、规则引擎审计
  买入区间：✅ 有效 / ⚠️ 预警 / 🔴 失效
  止损体系：✅ 有效 / ⚠️ 预警 / 🔴 失效
  动态止盈：✅ 有效 / ⚠️ 预警 / 🔴 失效
  US10Y熔断：✅ 有效 / ⚠️ 预警 / 🔴 失效

三、结构优化建议
  1. ...
  2. ...
```

## 六、修正决策流程

任何回测发现的参数修正，必须走完整流程：

```
┌─────────────────────────────────────────┐
│ 1. 回测数据输出（透镜 A）                 │
│    → 参数对比表 + 统计显著性              │
├─────────────────────────────────────────┤
│ 2. 黑帽审计（透镜 B）                    │
│    → 攻击新参数：过拟合？窗口偏差？        │
│    → 攻击旧参数：为什么之前选它？           │
├─────────────────────────────────────────┤
│ 3. CEO 裁决（透镜 C）                    │
│    → 通过：修正法典 + 更新 MEMORY.md      │
│    → 否决：记录否决理由                   │
│    → 观察：标记，下周期再议                │
├─────────────────────────────────────────┤
│ 4. 法典修正                              │
│    → 新版本号（如 V20.56.10 → V20.56.11） │
│    → 旧版移至作废区                       │
│    → 修正日志写入 knowledge/analysis/     │
└─────────────────────────────────────────┘
```

**修正日志命名规范**：`knowledge/analysis/YYYY-MM-DD-codex-backtest-<主题>.md`

- **统帅供弹依赖**：MA/ATR 参数依赖 P0 截图真值。若某标的连续 2 周无供弹更新，该标的回测自动跳过，标注「数据真空」。

- **跨市场对齐**：遵循法典 1.2.4 交易日对齐协议，各市场独立计数。

## 九、定时提醒与自动执行机制

### 9.1 设计原则

联邦投顾在每次对话启动时自动检查当前日期，命中回测日则自动触发执行。回测执行由联邦投顾自动跑数据，结果提交统帅裁决——**统帅只管「批不批」，不负责「跑不跑」。**

**实现方式**：依赖 AGENT.md 模块零的「对话启动日期检查」机制（非 scheduler 定时推送）。每次联邦投顾与统帅对话启动时，自动读取当前日期并与回测日历比对。命中则立即执行。此机制不依赖外部定时推送，由对话驱动。

### 9.2 提醒触发表

| 触发日 | 回测层级 | 触发条件 | 动作 |
|:---|:---|:---|:---|
| **每周六** | L1 周度 | 当前日期为周六 | 自动执行全池买入区间命中率回测，输出结果表 |
| **每月1日** | L2 月度 | 当前日期为每月1日 | 自动执行逐标最优参数重标定（24月滚动窗口；6/1额外跑全量窗口对比），输出参数对比→黑帽审计→提交CEO裁决 |
| **1/4/7/10月1日** | L3 季度 | 当前日期为1/4/7/10月1日 | 自动执行系统整体绩效审计，输出完整季度报告 |
| **即时** | 触发式 | 事故/连续3次止损/宏观熔断 | 即时执行，不受日历约束 |

### 9.3 执行协议

```
每次对话启动 → 检查日期 → 命中回测日？
├── 是 → 自动拉取数据 → 执行回测 → 输出结果 → 提交统帅裁决
│        └── 若数据不足（无P0截图/Tushare不可用）→ 输出「数据真空提醒」，推迟至下次对话
└── 否 → 正常对话流程
```
