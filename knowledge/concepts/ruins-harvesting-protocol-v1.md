## 一、协议概述

系统性恐慌中，优质资产被不分青红皂白地抛售，形成"废墟"——这是低风险高回报的建仓窗口。本协议定义恐慌日自动触发的扫描→筛选→建仓SOP。

**核心原则**：恐慌是礼物，不是灾难。但只有准备好"铲子"的人才能挖到宝藏。

## 三、执行流程（三步走）

### 步骤1：全池乖离率扫描（ATR20标准化 — V1.3唯一公式）

扫描17大核心池所有标的，计算**ATR20标准化乖离率 Z_atr**：

```
唯一公式（V1.4焊入 — 修复分母漂移）：

Z_atr = (Price - MA20) / ATR20

等价形式：Z_atr = deviation(%) / ATR20(%)

其中 deviation(%) = (Price - MA20) / MA20 × 100
      ATR20(%) = ATR20 / MA20 × 100  ← 🔴 分母统一为 MA20！不可用 Price！
```

标记 **Z_atr < -2.0** 的标的为"废墟候选"。

**🟢 Z_atr 扫描启用（V1.9 M1完成 — 解除V1.7禁用）**：
```
IF Z_atr阈值已标定（§0 M1完成） THEN
├── 正常执行 Z_atr 扫描，标记 Z_atr < -2.0 标的为废墟候选
├── 阈值来源：全池19标29,096样本回测确认，Sharpe 0.0508，胜率53.1%
└── 三重过滤层负责假废墟率控制（单层假废墟率46.9%→过滤后目标<15%）
```

**为什么不用 StdDev(20)**：趋势市中价格单向展开时，StdDev(20) 因包含趋势方向的偏离而膨胀，导致 Z-score 钝化——恐慌日漏扫。ATR20 衡量日内波幅均值，不受趋势方向影响，对恐慌日的识别更纯粹稳定。

**为什么不用统一-12%**：各标的波动率差异巨大（EWY ATR20/MA20=3.67% vs 513910=0.55%），统一阈值导致高波动标的频繁假废墟、低波动标的漏扫真废墟。

**🔴 分母漂移修复（V1.4焊入）**：
原 V1.3 公式 ATR20(%) = ATR20/Price×100，当 Price<MA20 时（恐慌日常态），分母 Price 被压缩 → ATR20(%) 膨胀 → Z_atr 绝对值被系统性压缩 → 阈值边界漏扫。
修复后：ATR20(%) = ATR20/MA20×100，分母恒定为 MA20，Price 的波动不再污染 ATR20(%) 的分母。
验证：Price=93, MA20=100, ATR20=3.5 → V1.3: Z=-7/3.76=-1.86（漏扫）。V1.4: Z=-7/3.5=-2.00（触发）。

**阈值重标定（V1.3 — 从 -3.0σ 改为 -2.0×ATR20）**：

| 标的 | ATR20/MA20 | Z_atr = -2.0 对应乖离率 | Z_atr = -3.0 对应乖离率 |
|:-----|:-----------|:----------------------|:----------------------|
| EWY | 3.67% | -7.3% | -11.0% |
| 588000 | 2.39% | -4.8% | -7.2% |
| MUFG | 1.40% | -2.8% | -4.2% |
| QQQ | 0.94% | -1.9% | -2.8% |
| 513910 | 0.55% | -1.1% | -1.7% |

│

│   └── 跳过后续步骤3

│   └── 继续步骤4
│
└── 步骤4：重新计算新总仓位加权均价和新止损线
    ├── 总仓位加权均价 = (T+1买入价 × 1/3 + T+4买入价 × 2/3)
    ├── 总仓位 -8% 止损线 = 加权均价 × 0.92
    ├── 第一批 -12% 止损线维持不变（以T+1买入价计算）
    └── 第二批 -10% 止损线 = T+4买入价 × 0.90
```

**设计原理**：T+4是多动作并发日（加仓+互斥锁解除+可能的止损触发），若并行执行可能出现「止损+加仓」叠加，仓位管理和止损线计算崩溃。串行执行确保「先止损后加仓，已止损则不加仓」。

```
双层止损 + 批次差异化保护（V1.4增强 — 修复P1-6加仓后保护失效）：

├── 总仓位统一成本 -8% → 🚨 总仓位强制平仓（全局熔断）
├── 第一批（T+1建仓 1/3）-12% → 该批次单独平仓（单批保护）
└── 第二批（T+4建仓 2/3）-10% → 该批次单独平仓（V1.4新增 — 比第一批更紧，因建仓时点更晚、信息更充分）

注意：T+1和T+4两批买入均价不同。总仓位统一成本 = 加权均价。
总仓位-8%止损线 = 加权均价 × 0.92

批次差异原理：T+4建仓时已观察3天反弹确认，信息优势更大 → 若仍下跌，选时错误的概率更高 → 止损更紧（-10%而非-12%）

单批平仓后规则（V1.5新增 — 修复P1-6止损真空）：
├── 任一批次触发止损平仓后 → 立即重新计算剩余仓位的加权均价
├── 新总仓位止损线 = 新加权均价 × 0.92
└── 若仅剩第二批（2/3），其总仓位止损线 = 第二批买入价 × 0.92
```

## 四、心理戒律

1. **恐慌日不要救火** — 浮亏不是灾难，踏空系统性机会才是
2. **不要等最低点** — 废墟中不可能抄到最低点，分批建仓就是接受"买不到最低"
3. **锚定效应是毒药** — 不要用恐慌低点的价格作为参照系，技术结构才是
4. **踏空不追** — 如果错过了恐慌日建仓窗口，反弹确认后仍有追认机制（见下方）

## 五、踏空补救：追认机制

若错过了恐慌日建仓窗口（未触发废墟收割协议），使用追认机制：

| 信号 | 操作 | 仓位 |
|:-----|:-----|:----:|
| 放量突破20日线 | 追入50% | 半仓 |
| 缩量回踩20日线不破 | 加仓至100% | 满仓 |
| 硬止损 | -8% | 保护本金 |

**追认窗口宽度**：恐慌日后 **8个交易日** 内进入追认窗口。此值基于2018-2026年所有恐慌日（VIX>28或全A等权跌幅>4%）后反弹时间的75%分位确定。若第8日仍未触发追认信号，窗口关闭，回归常规路由。

**🔴 统一追认日历（V1.7焊入 — 修复P1-5跨标的不一致）**：
```
全池共享追认窗口基准：
├── 以最近一个 panic 日（任意标的触发恐慌条件①②③）为基准
├── 全池21标共享 8 交易日追认窗口（从 panic 日后第1个交易日起算）
├── 每只标的在输出时标注：「该标的追认窗口剩余 X 交易日」
└── 若不同标的的 panic 日不同（如 A股周一、美股周二）→ 各自独立计算窗口，输出时标注各自剩余天数
```

**🔴 追认窗口内路由优先级（V1.6新增 — 修复P1-6分层退出与追认重叠）**：
- 追认窗口内（恐慌日后8交易日），追认信号优先级 > 常规进攻/反击信号
- 若标的在追认窗口内满足放量突破MA10（追认信号）→ 执行追认50%，**禁止同时执行常规进攻建仓**
- 若标的同时满足追认条件和进攻条件 → 追认优先（因恐慌废墟反弹场景的风险回报比高于常态进攻）
- 追认窗口关闭后（第9交易日起），标的回归常规路由
- 设计原理：防止同一标的在追认窗口内同时收到「追认50%」和「进攻100%」两个冲突指令

**量比阈值**：追认信号中的量比 > 1.2 改为 **成交量 > 近20日最低成交量的1.5倍** 或 **成交量较前3日均量增长 > 20%**，消除恐慌日高基数效应。

**"未再创新低"精确定义（V1.4修改 — 修复P0-新3追认死锁）**：
```
追认机制修改（V1.4 — 删除「未再创新低」前置条件）：
├── 原 V1.3 前置条件「连续 3 个交易日收盘价均未跌破 T 日收盘价」
│   └── 在典型恐慌路径中（T+1继续下跌再反弹），此条件在 T+6 之后才可能满足 → 追认窗口仅剩 2 日 → 名存实亡

│   │   │   ├── BUILDING → 指令失败/撤单 → IDLE（日志告警，可重新评估）
│   │   │   ├── LOCKED → 止损/止盈触发 → EXITING（发出退出指令，锁不解除）
│   │   │   ├── LOCKED → 48自然小时期满且无退出 → IDLE
│   │   │   ├── EXITING → 成交确认 → COOLDOWN（48自然小时冷却倒计时启动）
│   │   │   ├── EXITING → 指令失败 → LOCKED（保持持仓，重新评估退出）
│   │   │   ├── COOLDOWN → 48自然小时期满 → IDLE（冷却结束，可接收新信号）
│   │   │   ├── COOLDOWN → 人工覆盖 → IDLE（需双人确认，日志强制记录）
│   │   │   └── 🔴 COOLDOWN → 新panic信号出现 → COOLDOWN（V1.9r3焊入 — 修复P2-新3未定义行为）
│   │   │       ├── 动作：日志记录「冷却中，panic信号抑制：标的X，信号时间戳YYYY-MM-DD HH:MM」
│   │   │       ├── 禁止：转入BUILDING/LOCKED/EXITING任何状态
│   │   │       └── 例外：统帅指令覆盖（需双人确认）→ 直接转BUILDING，跳过COOLDOWN
│   │   │
│   │   ├── 🔴 竞态防护规则：
│   │   │   ├── RULE_1: EXITING状态下，无论任何新panic信号，禁止转入BUILDING
│   │   │   ├── RULE_2: BUILDING状态触及止损线→先确认是否已成交→未成交撤单转IDLE，已成交转LOCKED再转EXITING
│   │   │   └── RULE_3: 所有状态转换必须记录时间戳/触发事件/前状态/后状态/指令ID/成交回报ID
│   │   │
│   │   └── V1.6旧版已废弃（「退出即解除」边界模糊，无COOLDOWN态）
│
└── 退出后：废墟仓位回归常规路由管理（止损/止盈/追踪）
```

**设计原理**：三轨道（进攻/反击/观望）是常态路由，废墟收割是第四轨道（恐慌轨道）。若标的在废墟日同时满足进攻条件（如恐慌暴跌后 MA200 仍向上，价格突破 H15），路由优先级冲突——废墟模式优先，因为恐慌中的废墟建仓比常态进攻具有更高的风险回报比。

### 6.4 节假日 T+N 时间线裂缝熔断（V1.5新增 — 修复P2-12，V1.9r1交易日计数双轨制 — 修复P1-2跨假期追认死锁）

**问题**：T+3反弹确认、T+4开盘加仓、8日追认窗口均基于「交易日」假设。春节/国庆长假（7-9日休市）导致 T+1 与 T+3 间隔 10 个自然日，期间宏观环境可能剧变。

```
🔴 交易日计数法（V1.9r1焊入 — 修复P1-2跨假期追认边界冲突）：

├── 概念定义：
│   ├── T_trade = panic发生的交易日（非自然日）
│   ├── T+1_trade = T_trade之后的第1个交易日
│   ├── T+3_trade = T_trade之后的第3个交易日
│   ├── 延迟建仓日 = T+1_trade
│   └── 反弹确认日 = T+3_trade
│
├── 假期顺延规则：
│   ├── IF T_trade与T_trade+1之间存在N个自然日假期 THEN
│   │   ├── T+1_trade = 节后第1个交易日（顺延）
│   │   ├── T+2_trade = 节后第2个交易日（顺延）
│   │   └── T+3_trade = 节后第3个交易日（顺延）
│   └── 关键：T+1_trade和T+3_trade各自独立顺延，不存在「重叠」
│
├── 边界场景硬编码：
│   ├── 场景A：节前最后交易日panic → 节后首日=T+1_trade（允许建仓），T+3=节后第3交易日（非节后首日）
│   ├── 场景B：panic发生在周四，周五正常 → T+1=周五（建仓），T+2=下周一，T+3=下周二
│   ├── 场景C：panic发生在周五，周末2天 → T+1=下周一（建仓），T+2=下周二，T+3=下周三
│   └── 场景D：节后首日恰好是T+3 → 仍为T+3_trade（反弹确认日），非T+1_trade（延迟建仓日）
│
├── 🔴 禁止场景：
│   └── 同一交易日不可同时作为「延迟建仓日」和「反弹确认日」
│       └── 若日历计算导致冲突 → 系统报错，人工介入
│
├── 长假熔断规则（V1.5原版，V1.9r1上下兼容）：
│   ├── 触发条件：T日与T+3日之间自然日间隔 > 5天 且 包含法定节假日（排除普通周末）
│   ├── 熔断动作：
│   │   ├── 反弹确认推迟至节后第2个交易日（市场消化假期信息后）
│   │   ├── 追认窗口：8交易日 + 按实际休市天数顺延
│   │   └── T+1已建仓的1/3仓位不受影响，止损/止盈正常执行
│   │
│   └── 节后第1个交易日（延迟建仓日，非禁止建仓日）：
│       ├── 允许T+1按涨跌停执行条款延迟建仓（打开跌停后5分钟）
│       ├── 禁止T+3反弹确认（因跨假期间隔过长，信息失真）
│       └── 若节前T日已触发废墟并建仓1/3，节后首日该仓位不受影响
```

### 6.2 废墟反弹追认窗口

**V1.0 问题**: 恐慌日错过了，之后标的拒绝回调，永远等不到「便宜价」。开火档案的「等回调到均线」逻辑在废墟反弹场景中是锚定陷阱。

**追认规则**:

| 条件 | 动作 |
|:---|:---|
| 恐慌日后 8 个交易日 | 进入「追认窗口」 |
| 放量突破 MA10（成交量 > 近20日最低×1.5 或 较前3日均量增长 > 20%） | 触发「废墟反弹确认」信号（V1.4：唯一追认信号，删除「未再创新低」前置条件） |
| 确认后 | 允许追入 50% 废墟仓位（基于该标的 R_tier） |
| 后续 | 缩量回踩 MA10 不破 → 加至满仓 |

**关键原则**: 在废墟反弹场景中，「买贵了」的风险远小于「买不到」的风险。恐慌日 $68.50 没买，$74 时追入仍然比 $160 踏空好 100 倍。

**🔴 追认窗口并发管理模式（V1.9r1焊入 — 修复P1-3「共享」与「独立」互斥，二选一禁止混合）**：

## 附录I：VPIN/IV四阶段前置过滤模块（V1.9r4焊入）

**设计定位**：本模块作为C4a→C4b的校准层。恐慌日C4a（Z_atr < -2.0）触发后，在进入C4b（成交量确认）之前，先通过VPIN/IV四阶段判定当前微观结构状态，动态调整C4b的成交量阈值。阶段一/二收紧（假废墟风险高），阶段三/四放松（真废墟概率大）。

### §I.1 四阶段定义

| 阶段 | IV状态 | VPIN状态 | 微观结构含义 | 假废墟风险 |
|:---|:---|:---|:---|:---|
| **阶段一 — 毒性爆发** | IV飙升（>HV20×1.5） | VPIN高（>0.7） | 知情交易者率先撤离，流动性提供方撤退，价差拉宽 | 🔴 高（IV可能继续飙升，方向不确定） |
| **阶段二 — 恐慌扩散** | IV高位（>HV20×1.3） | VPIN极高（>0.85） | 全面恐慌，流动性枯竭，订单流高度不平衡 | 🔴 极高（踩踏中，接飞刀风险大） |
| **阶段三 — 毒性消退** | IV回落但仍高（HV20×1.0-1.3） | VPIN下降（0.5-0.7） | 知情交易者撤离完毕，流动性逐渐回归 | 🟡 中等（恐慌尾部风险仍存） |
| **阶段四 — 废墟形成** | IV低（<HV20×1.0） | VPIN低（<0.5） | 恐慌结束，流动性恢复，价格已充分折价 | 🟢 低（真废墟，最佳建仓时机） |

> **HV20** = 20日历史波动率（收盘价对数收益率的标准差×√252）。IV/HV20比值用于消除不同标的之间波动率基数的差异。

### §I.2 C4b阈值动态校准表

| 当前阶段 | C4b成交量阈值 | 校准逻辑 |
|:---|:---|:---|
| 阶段一（毒性爆发） | **2.5×均量** | 毒性爆发阶段成交量可能巨大但方向不确定，高阈值过滤假废墟——只有真正的系统性踩踏才触发 |
| 阶段二（恐慌扩散） | **2.0×均量** | 恐慌扩散阶段成交量极度放大，阈值略放松但仍需确认非孤立大单砸盘 |
| 阶段三（毒性消退） | **1.5×均量**（基准值） | 毒性消退后成交量回落，1.5×足以区分真废墟与正常波动 |
| 阶段四（废墟形成） | **1.2×均量** | 废墟形成阶段成交量已回归正常，低阈值即可——此时价格已充分折价，成交量不放大也是合理废墟 |

> **引用关系**：基准值1.5× = §0 C4b初始值。阶段一收紧至2.5×，阶段四放松至1.2×。所有阈值待M3双参数联合压力测试标定。

### §I.3 阶段判定流程

```
恐慌日C4a触发（Z_atr < -2.0）
  →
  Step I.1: 获取当前IV（隐含波动率）与HV20（20日历史波动率）
  Step I.2: 获取当前VPIN（成交量同步概率，若不可得用买卖不平衡代理）
  Step I.3: 查表判定当前阶段
    ├── IV > HV20 × 1.5 且 VPIN > 0.7 → 阶段一
    ├── IV > HV20 × 1.3 且 VPIN > 0.85 → 阶段二
    ├── IV 在 HV20×1.0-1.3 且 VPIN 0.5-0.7 → 阶段三
    ├── IV < HV20 × 1.0 且 VPIN < 0.5 → 阶段四
    └── 不满足以上任一 → 默认阶段三（中性处理）
  Step I.4: 查§I.2表获取校准后C4b阈值
  Step I.5: 成交量 > 20日均量 × 校准阈值 → C4b通过
```

### §I.4 VPIN代理计算（API不可得时的降级方案）

VPIN（Volume-Synchronized Probability of Informed Trading）需要逐笔成交数据，当交易所逐笔数据不可得时，使用以下降级代理：

```
VPIN代理 = |买盘成交额 - 卖盘成交额| / (买盘成交额 + 卖盘成交额)

数据源：
  ├── 美股：Tushare暂不支持逐笔 → 使用日内1分钟K线外盘/内盘比例代理
  ├── A股：mx-data主力净额方向代理
  │   └── VPIN代理 = |主力净额| / 成交额（以主力净额方向推断买卖不平衡）
  └── 全不可得：跳过阶段判定，C4b使用基准值1.5×

代理阈值映射（代理VPIN通常<真实VPIN，阈值需下调）：

```
