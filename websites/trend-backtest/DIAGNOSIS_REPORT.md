## 一、背景与目标

### 1.1 系统定位

本模块是「双轨配置体系」中的**进攻策略轨**（趋势跟踪），与反击策略轨（均值回归）并行运行。

```
全局资金架构（双轨配置 V1.2 Final）：
├── 长期底仓 30%（VEA 20% + VTI 10%，固定层，永不离场）
├── 竞争上岗池 50%（19标动态填充）
│   ├── 进攻策略（本模块）← 顺势加仓，MA200方向
│   └── 反击策略（法典卫星）← 逆势接飞刀，买入区间公式
└── 机动储备 20%（511880 + SGOV）
```

### 1.2 模块职责

趋势跟踪模块的唯一使命：**在上涨趋势中捕获 Beta，在横盘/下跌趋势中空仓等待。** 不与反击策略竞争，两者共享 19 只标的池，按实时信号动态分配。

### 1.3 回测目的

验证趋势跟踪入场/离场规则在历史数据上的表现，确保上线前满足最低绩效标准。

## 四、当前规则（Fix2 基线 / 路C 候选）

### 4.1 入场条件（6条 AND，全部满足才开仓）

```
1. 收盘价 > MA200
2. MA200 斜率 > 0（当日 MA200 > 20日前 MA200）
3. 连续 3 个交易日收盘价 > MA200
4. ADX(14) > 22
5. 量能：当日成交量 > 20日均量 × 1.0 + 最近3日至少2日 > 20日均量
6. 非休眠状态（连续3次止损后休眠60日）
```

### 4.2 离场条件（5优先级，全部即时执行）

```
P0: 从最高点回撤 > 8%（绝对底线）→ 立即全清
P1: 价格 < 最高价 − k×ATR(14)（追踪止损）→ 立即清仓
     k值：高波动标的 3.0(Fix2)/3.5(路C)，标准标的 2.5(Fix2)/3.0(路C)
P2: MA200 方向转空（连续3日 MA200 斜率 < 0）→ 立即清仓
P3: ADX(14) < 20 → 立即清仓
P4: 收盘价 < MA200 → 立即清仓
```

### 4.3 仓位分配（月频）

```
每月1日执行：
  1. 扫描19只标的，选出满足6条入场条件的
  2. 按 ADX 降序排列，取前6只
  3. 每只仓位 = min(1%风险法则计算股数, 总资产×5% ÷ 入场价)
  4. 总暴露 ≤ 30%
  5. 已持仓标的若仍在排名前6且未触发离场 → 持仓不变
  6. 新进标的 → 买入；排名跌出前6的旧持仓 → 平仓
```

### 4.4 追踪止损分级

| 类型 | 标的 | Fix2 倍数 | 路C 倍数 |
|:---|:---|:---|:---|
| 高波动 | QQQ, 588000, 159915, 518880 | 3.0×ATR | 3.5×ATR |
| 标准波动 | 其余14只 | 2.5×ATR | 3.0×ATR |

## 五、待专家诊断的核心问题

### 5.1 版本选择

**Fix2（年化 3.89%, 回撤 −14.18%）vs 路C（年化 6.82%, 回撤 −16.71%）**

| 维度 | Fix2 | 路C |
|:---|:---|:---|
| 收益率 | 稳健但平庸 | 显著提升 |
| 回撤安全边际 | 2.82pp（14.18 vs 15 上限） | 0.29pp（16.71 vs 17 上限） |
| 盈亏比 | 1.66 | 1.89 |
| 稳定性 | 更高 | 更依赖牛市 |

### 5.2 方法学问题

1. **MA200 周期选择**：10年回测期间涵盖 2016-2017 慢牛、2018 熊市、2019-2020 反弹、2021 震荡、2022 暴跌、2023-2026 牛市。MA200 作为趋势锚线是否合理？是否需要考虑 MA150 或 MA250？

2. **ADX 阈值 22**：传统 ADX 阈值 25 是强趋势标准，22 处于过渡区。放宽后的假突破率 28.2% 是否可接受？

3. **月频入场 + 日频离场**：入场和离场时间尺度不对称是否会导致逻辑不一致？应该统一为日频还是周频？

4. **追踪止损的 ATR 倍数**：3.0-3.5×ATR 在趋势跟踪中是否合理？常见系统通常使用 2.0-3.0×ATR，路C 的 3.5×ATR 是否过宽？

### 5.3 风险问题

1. **2021年6-7月聚类风险**：Train 期内，3 只标的在同一月同日买入后同步阴跌，导致最大回撤集中在该事件。是否需要在入场时增加行业/板块分散度约束？

2. **2022年暴跌场景**：2022年全球加息周期，若所有标的同步下跌，月频买入的 6 只可能同时触发 P0，单月亏损可达 −8%×6×5% = −2.4%（总资产）。这个尾部风险是否可接受？

3. **假突破率的安全边际**：28.2% vs 35% 硬上限，仅 6.8pp 空间。如果未来市场波动率变化，假突破率可能突破上限。

### 5.4 架构问题

1. **与反击策略的竞争重叠**：同一标的可能同时满足进攻策略（趋势跟踪）和反击策略（均值回归）的条件，当前通过 ATTACK_LOCKED 机制解决冲突。这个机制是否合理？

2. **19只标的池的充分性**：趋势跟踪策略的分散度是否足够？是否需要引入更多宽基 ETF 增加信号源？

3. **现金管理**：闲置资金（约 70-75%）存入货币基金（511880/SGOV），年化约 1.6-5.2%。现金部分在大牛市中是否构成机会成本浪费？

## 七、附录：完整规则代码描述

```python
# ============================================
# 趋势跟踪模块 V1.1 路C（候选版本）
# ============================================

# --- 参数 ---
MA_PERIOD = 200
ADX_PERIOD = 14
ADX_ENTRY_THRESHOLD = 22
ADX_EXIT_THRESHOLD = 20
VOL_PERIOD = 20
VOL_ENTRY_RATIO = 1.0          # T0量能/MA20量能
VOL_STRENGTH_DAYS = 3          # 最近N日至少2日>MA20
CONFIRMATION_DAYS = 3          # 连续站稳MA200天数
P0_MAX_LOSS = -0.08            # 绝对止损线

# 追踪止损ATR倍数
TRAILING_ATR = {
    'QQQ': 3.5, '588000': 3.5, '159915': 3.5, '518880': 3.5,  # 高波动
    'default': 3.0                                              # 标准波动
}

# 仓位
MAX_POSITIONS = 6
MAX_SINGLE_WEIGHT = 0.05       # 单标上限5%
MAX_TOTAL_WEIGHT = 0.30        # 总暴露上限30%
SLEEP_PERIOD = 60              # 连续3次止损后休眠天数

# --- 入场逻辑（每月1日） ---
def monthly_entry(date):
    candidates = []
    for ticker in universe:
        if ticker.is_sleeping(date):
            continue
        if not (close[ticker][date] > ma200[ticker][date]):
            continue
        if not (ma200[ticker][date] > ma200[ticker][date - 20]):
            continue
        if not all(close[ticker][date - i] > ma200[ticker][date - i] 
                   for i in range(CONFIRMATION_DAYS)):
            continue
        if adx[ticker][date] <= ADX_ENTRY_THRESHOLD:
            continue
        vol_ratio = volume[ticker][date] / ma_volume[ticker][date]
        if vol_ratio < VOL_ENTRY_RATIO:
            continue
        recent_above = sum(1 for i in range(VOL_STRENGTH_DAYS)
                          if volume[ticker][date - i] > ma_volume[ticker][date - i])
        if recent_above < 2:
            continue
        candidates.append(ticker)
    
    candidates.sort(key=lambda t: adx[t][date], reverse=True)
    return candidates[:MAX_POSITIONS]

# --- 离场逻辑（每日） ---
def daily_exit(ticker, date, entry_price, highest_since_entry):
    current = close[ticker][date]
    loss_pct = (current - entry_price) / entry_price
    
    # P0: 绝对止损
    if loss_pct <= P0_MAX_LOSS:
        return ('P0', 'market')
    
    # P1: 追踪止损
    k = TRAILING_ATR.get(ticker, TRAILING_ATR['default'])
    stop_price = highest_since_entry - k * atr[ticker][date]
    if current <= stop_price:
        return ('P1', 'market')
    
    # P2: MA方向转空（3日确认）
    if (ma200[ticker][date] < ma200[ticker][date - 1] and
        ma200[ticker][date - 1] < ma200[ticker][date - 2] and
        ma200[ticker][date - 2] < ma200[ticker][date - 3]):
        return ('P2', 'market')
    
    # P3: ADX趋势衰竭
    if adx[ticker][date] < ADX_EXIT_THRESHOLD:
        return ('P3', 'market')
    
    # P4: 价格跌破均线
    if current < ma200[ticker][date]:
        return ('P4', 'market')
    
    return None  # 继续持有
```
