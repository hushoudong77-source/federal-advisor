## §1 数据输入强制校验协议（Data Input Mandatory Validation Protocol）

### 1.1 数据输入18字段强制完整性校验

**任何标的进入路由判断前，必须完成以下18字段校验。缺一项即熔断，禁止进入路由。**

| # | 字段 | 数据源 | 触发条件 | 熔断动作 |
|:---:|:---|:---|:---|:---|
| 1 | 现价 | P0 用户投喂 / P2 Tushare | 缺失 | 禁止路由，标注「现价缺失」 |
| 2 | 成本价 | P0 用户投喂 | 缺失 | 禁止路由，标注「成本缺失」 |
| 3 | 持仓数量 | P0 用户投喂 | 缺失 | 禁止路由，标注「持仓缺失」 |
| 4 | 150EMA | Tushare 自算 | 数据不足150日 | 标注「EMA不足」继续（非阻断） |
| 5 | 50EMA | Tushare 自算 | 数据不足50日 | 同上 |
| 6 | 30EMA | Tushare 自算 | 数据不足30日 | 同上 |
| 7 | 乖离150EMA | 自算：(现价-150EMA)/150EMA | EMA缺失 | 标注「N/A」 |
| 8 | 乖离50EMA | 自算 | EMA缺失 | 标注「N/A」 |
| 9 | 乖离30EMA | 自算 | EMA缺失 | 标注「N/A」 |
| 10 | MACD | Tushare 自算 | 数据不足26日 | 标注「N/A」 |
| 11 | ATR(14) | Tushare 自算 | 数据不足15日 | 标注「N/A」 |
| 12 | 20日最高 | Tushare L20 | 数据不足20日 | 标注「N/A」 |
| 13 | 20日均量 | Tushare L20 | 数据不足20日 | 标注「N/A」 |
| 14 | MA方向 | 自判：MA50 vs MA50前日 | EMA不足51日 | 标注「N/A」 |
| 15 | 日涨跌幅 | P0投喂/P2 Tushare | 缺失 | 标注「N/A」 |
| 16 | 标的类型 | 硬编码白名单 | 缺失 | 禁止路由，标注「类型未知」 |
| 17 | 策略归属 | 自动路由（§2） | 路由未完成 | 禁止开火，标注「路由待定」 |
| 18 | 宏观闸状态 | §4宏观闸裁决 | 未裁决 | 禁止开火，标注「宏观闸未裁决」 |

**自算公式固化**：

```
150EMA(t) = 2/(150+1) × Price(t) + (1 - 2/(150+1)) × EMA(t-1)
50EMA(t)  = 2/(50+1)  × Price(t) + (1 - 2/(50+1))  × EMA(t-1)
30EMA(t)  = 2/(30+1)  × Price(t) + (1 - 2/(30+1))  × EMA(t-1)

MACD = EMA(12) - EMA(26)
Signal = EMA(MACD, 9)
Histogram = MACD - Signal

ATR(14)(t) = (13 × ATR(t-1) + TR(t)) / 14
TR(t) = Max(High-Low, |High-Close(t-1)|, |Low-Close(t-1)|)
初始ATR = MA(TR, 14)

乖离率150EMA = (Price - 150EMA) / 150EMA × 100%
乖离率50EMA  = (Price - 50EMA)  / 50EMA  × 100%
乖离率30EMA  = (Price - 30EMA)  / 30EMA  × 100%

MA方向 = SIGN(MA(today) - MA(yesterday))
```

### 1.2 违规熔断清单（不可绕过）

| 违规类型 | 触发条件 | 动作 |
|:---|:---|:---|
| 现价缺失 | 路由启动时无P0/P2现价 | 禁止进入路由 |
| 成本缺失 | 已持仓标的路由时无成本 | 禁止开火，标注「成本黑洞」 |
| 持仓缺失 | 已持仓标的路由时无数量 | 禁止加减仓，标注「仓位黑洞」 |
| 标的未识别 | 代码不在全池21标白名单 | 禁止路由，标注「池外标的」 |
| 宏观闸跳过 | 未执行§4裁决即开火 | 开火无效，重新裁决 |
| 路由跳过 | 未执行§2路由即开火 | 开火无效，补路由 |

## §4 宏观闸三态裁决协议（Macro Gate Ternary Protocol）

### 5.2 仓位硬顶与跨策略合并

**单标总暴露上限**：20%（跨策略合并）

```
单标总仓位% = min(进攻仓位% + 反击仓位%, 20%)
进攻仓位% ≤ 7.5%（单标）
反击仓位% ≤ 10%（单标）
```

**仓位合并上限检查**（每次开火前强制执行）：

```
IF 进攻仓位% + 反击仓位% > 20%:
    → 输出「⚠️ 仓位硬顶20%触发，拒绝开火」
    → 提供选择：①放弃本次开火 ②减仓已持后开火
```

### 5.3 执行审计门

**审计门① — 开火前强制六问**：
1. 现价+成本+持仓完整？
2. 宏观闸已裁决（§4）且未触发熔断？
3. 路由已判定（§2）且策略归属明确？
4. 仓位硬顶20%未触发？
5. 金盾总纲（若为黄金标的）已独立裁决？
6. 攻击窗口（若适用）仍有效？

六问任一为否 → **禁止开火**。

**审计门② — 离场前强制四问**：
1. 离场信号来自哪个SRC编号？
2. 该SRC的触发阈值是否精确命中？
3. 离场后仓位是否归零（无残留）？
4. 离场原因已写入当日记忆？

四问任一为否 → **禁止离场**。

### 5.4 执行偏差记录

每次开火/离场后必须写入当日记忆：
```
[开火/离场] 标的 | 时间 | 价格 | 数量 | 策略归属 | SRC编号 | 审计门通过
```

**偏差审计**（`/执行审计` 触发）：
- 对照法典指令 vs 实际交易记录
- 输出偏差清单
- 偏差分类：合规 / 轻微偏差 / 严重违规
